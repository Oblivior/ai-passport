# AI Pet Passport：数码宝贝伙伴

本 Fork 消费 Kaboo 本地 CSV 导出，通过 USB 或应用层加密 BLE 给三条主线的像素宠物投食。目前是可玩原型，尚非完整成品。

## 怎么玩

菜单打开「数码宝贝」。上下键切换首页、今日饭盒、进化条件、进化图鉴、伙伴之家、家族。单击 OK 吃一份已获得的食物；空饭盒时摸摸或唤醒宠物，不增加成长。进食 1.2 秒，进化演出 1.8 秒。安静 30 秒后休息，不惩罚。家族页单击 OK 翻阅，长按 OK 返回硬件菜单。双击不再产生食物。

| 阶段 | 已吃食物 | 食物已吃的用量活跃天数 |
| --- | --- | --- |
| 数码蛋 | 0 | 0 |
| 黑球兽 | 1 | 1 |
| 滚球兽 | 3 | 2 |
| 亚古兽 | 6 | 3 |
| 暴龙兽 | 12 | 6 |
| 机械暴龙兽 | 24 | 10 |
| 战斗暴龙兽 | 40 | 16 |

两个条件同时满足才能进化，三条主线共用上表各阶段门槛。离线补吃按食物来源日计算天数，但不能早于该伙伴的领养日：领养前库存只合计为领养当天一次陪伴，不能瞬间获得十几天成长。设备首次同步忽略之前历史。未领取食物保留至下次跨月同步，届时过期。

### 今日饭盒

五格饭盒按标注的来源日期区分「饱」（已吃）、「饭」（待吃）和未获得的空格；显示该日准确的 Token 快照、下一份还差多少及进度，另外列出旧饭。吃饭优先消耗旧日期的食物，因此吃掉昨天的饭不会增加今天的已吃格数。本页按确定只回首页，不自动喂食。获得五份后明确显示当天封顶，不鼓励继续刷用量。

首次正用量获得食物，此后须严格超过锁定日目标的每个 20% 边界才获得下一份；数据向下修正不扣已经获得的食物。这是定期同步的本地快照，不是实时计数或 Bits 官方总量。重启后尚未同步，或十分钟没有同步，显示「上次的饭盒」并保留来源日期。新食物送到时，首页提示四秒，不打断进食或进化、不自动切页；相同快照不会重复提醒。SYNC 协议和食物额度不变。

### 三条完整主线与伙伴之家

- 数码蛋 → 黑球兽 → 滚球兽 → 亚古兽 → 暴龙兽 → 机械暴龙兽 → 战斗暴龙兽。
- 数码蛋 → 普尼兽 → 独角兽 → 加布兽 → 加鲁鲁兽 → 兽人加鲁鲁兽 → 钢铁加鲁鲁兽。
- 数码蛋 → 浮游兽 → 迪哥兽 → 巴达兽 → 天使兽 → 神圣天使兽 → 炽天使兽。

新开始时，上下挑主线、确定进入确认页、再确定领养数码蛋。伙伴之家按确定进入选择，上下浏览三位伙伴及返回项；确认页说明是新蛋还是继续陪伴，上下取消确认，确定保存选择。未领养主线展示成长期的预览外观，并明确写着从数码蛋开始。长按确定始终返回硬件菜单。

每条主线每月最多领养一只，各自保留已吃食物、陪伴天数和形态。所有伙伴共用每日额度与库存；切换和重复同步不会额外发饭。只有身边的伙伴吃饭，休息中的伙伴不掉成长。图鉴区分实际养成与未来预览，解锁记录跨月保留，浏览不解锁。这不是换皮操作。

现有 v2 的当前成长迁到亚古兽，食物与天数不丢失；所有 v3 之前的家族记录保留原机器人展示。食物强度 `family.route` 字段和 ROUTE 查询保留以兼容旧版本，但表示共享用量账本，不表示物种或分支。丧尸暴龙兽分支尚未实现，Token 用得多不等同于照顾不当。

内置素材是手工编写的像素同人图，不是官方精灵，也不是原创角色 IP。代码许可证不授予角色权利，不声明已获得商业使用或公开再分发授权；公开发布前需核查授权。详见[素材说明](assets/images/README.zh_CN.md)。

## 桌面伴侣

需要 Python 3.9+、`pyserial==3.5`，以及支持 `export --format csv` 的已安装 `kaboo-cli`。在本仓库运行，指定已识别的设备端口：

```bash
python3 tools/pet_companion.py --preview
python3 tools/pet_companion.py --port /dev/cu.usbmodem101
python3 tools/pet_companion.py --port /dev/cu.usbmodem101 --watch
```

默认同步一次；`--watch` 在进程运行期间每 300 秒同步，不安装自启服务，刷机前须停止。`--csv path/to/export.csv` 可指定本地导出。真实导出不得提交仓库。

持续同步会保持串口连接，断连后在下一轮重试。设备启动时会重试只读握手；首次连接可能返回主菜单，之后正常同步不应反复重启设备。

首次正用量获得一份食物，此后每超过日目标的 20% 解锁下一份，每天最多五份。日目标取此前十四个活跃日的中位数，不含当天；没有历史时为 1,000,000。每月首次同步可用 `--goal` 指定，之后当月锁定。日期采用北京时间，本地覆盖范围不等于 Bits 官方月报。

伴侣关闭 CLI 自动更新、隔离扫描缓存，在内存处理 CSV，不保留原始导出、Prompt、项目名、主机名或凭据。CSV 消费端独立实现，没有复制内部 Kaboo 代码。设备只接收日期、日聚合 Token、目标和每日食物额度。缺失或无效数据停止同步，不伪造零值。

如果导出器支持 `export --cached`，可在有线或无线伴侣命令后加 `--cached-export`，并用 `--kaboo-cli /path/to/cli` 显式选择该程序。专用持久缓存复用未变化文件、增量解析安全追加内容，但 CSV 始终是累计替换快照，不是 Token 增量。首次建立基线可能较慢。不支持的参数、无效输出或超时会停止本轮，不自动降级、不发假食物；默认完整扫描继续兼容旧 CLI。导出器缓存含本地来源数据，必须保持私有并与上报缓存隔离；公开仓库不包含内部导出器实现。

## 存储与传输

### 无线饭盒（Phase 2）

macOS 伴侣面向 12.3 及以上版本。扫描时在本机同时匹配服务与配对 ID，不记录附近其他设备的信息。

在电脑的 Python 虚拟环境安装 `tools/requirements-pet-wireless.txt`。先停止 USB 同步窗口，再用连接设备的 USB 配对一次：

```bash
python3 -m pip install -r tools/requirements-pet-wireless.txt
python3 tools/pet_wireless.py --pair-usb /dev/cu.usbmodem101
python3 tools/pet_wireless.py --watch
```

配对成功后可拔掉 USB，保持胸牌开机、电脑蓝牙开启与伴侣窗口运行。正常每轮间隔 300 秒，读取本地用量后短暂连接、同步并断开；不安装自启服务。macOS 首次使用可能要求给终端蓝牙权限，必须由用户批准。超出范围或电脑休眠只延后同步，不扣食物；下轮自动重试。默认完整扫描，可用 `--cached-export` 选择上述缓存加速的累计导出。

发现或连接超时时，每轮最多尝试三次，间隔 2 / 4 秒并重新扫描；身份不匹配或认证失败不按此策略重试。macOS 冷启动连接耗时仍可能波动。

`--config` 可指定配对文件，默认 `~/.config/ai-passport/link.json`，权限必须为 0600。密钥先落到本机再经 USB 写入设备，ACK 丢失可用原文件重试。已经配对的设备拒绝其他密钥；不要删除唯一密钥副本，目前没有无线重置或换绑入口。菜单 Pet Link 查看配对/连接/错误状态，退出页面不会停掉饭盒服务；成长页区分 USB / WIRELESS SYNC OK。加密失败不回退明文或 USB。

安全边界：采用标准 AES-256-GCM 的应用层加密认证，不是操作系统 BLE 绑定。每连接生成 16 字节挑战，方向标签和挑战作为 AAD，每帧 12 字节随机 nonce、16 字节认证标签；明文包含 4 字节大端递增序号及现有 PET2 命令。错误密钥、篡改、跨连接和旧序号均不能执行投食。仅允许 STATUS/ROUTE/SYNC，PAIR 与 LINK 诊断仅走 USB。未认证连接超时断开，错误请求受单元素队列和失败次数限制；不能承诺抗无线干扰或持续拒绝服务。配对文件和设备 NVS 未启用静态加密，物理访问设备或读取本机文件的人仍可取得密钥。不得上传配对文件、NVS 备份或原始导出。

BLE 服务 `2b251000-8db0-4bdb-8b45-947717e4e6fa`，INFO/REQUEST/RESPONSE 将 `1000` 分别换为 `1001/1002/1003`。INFO 为版本字节 3、8 字节 ASCII 配对 ID、16 字节挑战。请求 AAD 为 `PET3-C` 加挑战，响应为 `PET3-S` 加挑战；帧为 nonce、密文、tag。GATT write 成功不代表已投食，必须读到认证后的应用 ACK。现有每日累计额度和 NVS 先提交后 ACK 规则不变。

新增 `ai_pet_v3` 使用 CRC 双槽保存共享饭盒与独立伙伴，不写原 `ai_pet`、`ai_pet_v2` 和配对存档。仅 v3 不存在时允许迁移；不可读或不兼容时阻止写入，不静默重置。单槽损坏可回退另一槽，CRC 有效但存在未知物种时禁止降级覆盖。提交失败不改变生效状态。家族保留最近 12 条个体记录，不是 12 个月。降级到 v2 只会恢复其旧快照，不会带回后续 v3 成长；不要交替使用两个版本并期待存档合并。升级前备份，核对分区表后只更新 `0x10000` 应用区域；禁止全盘擦除，保留设备身份与 Recovery。

USB 是受信任本地线缆协议，不是远程认证 API，使用[现有非阻塞控制台](https://docs.espressif.com/projects/esp-idf/en/release-v5.5/esp32c3/api-guides/stdio.html)：

```text
PET2 STATUS
PET2 ROUTE
PET2 HOUSE
PET2 SYNC YYYYMMDD <tokens_today> <daily_goal> <31 digits, each 0..5>
```

每行最多 159 字符。拒绝无效或回退日期、未来日期食物、未知命令和月中目标变更。每天累计额度取最高值，重复同步或 ACK 丢失不重复发饭，上游修正不扣已获得的食物。NVS 提交成功后才 ACK；写入失败不改变生效状态。串口不提供吃饭命令，必须按实体按钮。

HOUSE 仅通过 USB 只读查询版本、当前物种 ID、已领养位图与存储健康。STATUS 的 meals/days/stage 表示身边的伙伴，pending 仍是共享库存。没有远程领养、切换或吃饭命令。

进入新月份后的第一次同步将当月领养的每只伙伴归档、旧食物过期、保留历代图鉴解锁，并重新挑选一颗蛋。这是本地跨月，不是 Bits 官方结算。离线时等待电脑时间，不自行假设新月份。

### 后续新增主线

`main/pet_catalog.c` 用稳定 ID（1 亚古兽、2 加布兽、3 巴达兽）关联名字和素材。新增唯一 ID、目录条目、七阶段及每阶段三套动作图，更新目录数量与素材数组维度，重生成精灵与中文字库，再扩展主机用例并检查长名字布局。当前存档固定预留八个 ID；不能重排旧 ID 或把菜单位置当身份，超过容量需显式升级存档版本。不认识存档中物种的旧固件禁止覆盖。这是更新固件和内容包的流程，不是在线下载插件。

## 验证与边界

运行 `./tools/validate.sh --static` 和[构建与测试](docs/development/build-and-test.zh_CN.md)中的真实 LVGL 测试。页面测试输出 PPM 截图，覆盖布局、进食、进化、睡眠、快速按键和退出。纯逻辑测试覆盖三天成长、十六天进化门槛、重放、补发、日期校验、跨月和旧存档导入。

无线伴侣另运行 `python3 tests/test_pet_wireless.py`（需要上述依赖），覆盖认证、篡改、方向隔离、旧序号、长度、私有配置和 ACK。固件端安全拒绝行为、真实无线 ACK 与无线开启后的内存必须另在设备验证。

ROUTE 只读返回 `route`、`locked`、`stage`；路线编号为 0=CORE（未成形）、1=ARMOR、2=WILD、3=EXPLORER，原 STATUS/SYNC 字段保持不变。

尚缺 Bits 结算及基于认证特征的路线、独立 Flux 适配、分支进化、相遇、音效和正式精灵素材。真机断电、电池续航和连续三天人工体验属于独立验收，主机模拟不能代替。无线常驻后与 Wi-Fi 扫描、96 KB 录音等硬件演示并发的完整资源验收未完成；日常使用 AI Pet / Pet Link 页面。
